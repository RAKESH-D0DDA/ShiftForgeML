# Supervised learning protocol (Milestone 3)

## Scope and estimands

Estimate the conditional expected trip duration from features known at pickup. Compare an unconditional median predictor, L2-regularized regression and histogram gradient boosting. The primary selection criterion is **validation mean absolute error (MAE)** in minutes, with alphabetical tie-breaking. RMSE, 90th-percentile absolute error and negative prediction counts are secondary diagnostics. Do not interpret validation errors as locked-test performance.

## Temporal partitions and label availability

The implementation requires **all** January through June 2024 monthly partitions for training and July through August for validation. It rejects missing partitions, divergent sample fractions, mismatched configuration hashes and altered output checksums. All training labels must be available by July 1, 2024. All validation labels must be available by September 1, 2024. Previous ingestion enforces these cutoff conditions, and the model loader checks them again.

September is held for a separate conformal calibration experiment. October through December is reserved for final test evaluation. Neither set is loaded, scored or referenced by the training command.

## Feature isolation

The only model inputs, in fixed order, are `pickup_zone`, `pickup_hour`, `pickup_weekday` and `pickup_month`. This interface excludes `duration_minutes`, `pickup_time`, `label_available_at` and outcome-dependent fields from model inputs. The loader checks that engineered calendar features agree with the recorded pickup timestamp. Fitted encoders are contained in sklearn pipelines and are learned **only** from training observations. Validation records are never used to fit preprocessing transformations.

The zone identifier is nominal. Ridge regression applies one-hot encoding to all four predictors. Histogram gradient boosting uses native categorical splits for zone. Because source identifiers may have up to 265 distinct values and histogram boosting supports at most 255 bins per categorical feature, `OrdinalEncoder(max_categories=128)` aggregates rare categories using training frequencies only. Unseen validation categories map to a missing-value code. Calendar predictors are numeric for the nonlinear estimator.

## Training and selection

Default training cap: 200,000 records selected from the entire training partition using NumPy's seeded generator, without replacement. The cap is applied *after* complete provenance and temporal validation. It bounds fitting cost but the dataset loader still materializes the complete curated training and validation arrays in memory. This is a deliberate baseline design limitation.

The experiment fits three configured candidates:

| Model | Configuration |
|---|---|
| Median predictor | Training median, no features |
| Ridge | One-hot encoding, alpha = 10.0 |
| Histogram gradient boosting | 80 iterations, 15 leaf nodes, learning rate = 0.08, L2 = 0.1, native zone categories |

Configurations are fixed before validation. This stage performs **algorithm comparison**, not an exhaustive hyperparameter search. After selecting the model with the smallest validation MAE, the estimator remains fitted on the selected training subset. Calibration and test partitions remain untouched.

## Artifacts and reproducibility

`artifacts/training/validation_metrics.json` stores the experiment digest, source-partition checksums, software versions, estimator scores, sample counts and selected model identity. `artifacts/training/selected_model.joblib` contains the fitted sklearn pipeline and is excluded from Git. The JSON also records the SHA-256 digest of the serialized artifact.

Serialized sklearn/joblib objects can execute code when loaded. Never load model artifacts from untrusted sources. Avoid claiming bitwise equality of serialized models across Python and scikit-learn versions. Identical versions, source partitions and seeds are required for meaningful reproduction. Measured fitting time may vary between machines.

## Limitations

The current benchmark uses a small, intentionally constrained feature set. Trip duration also depends on route, weather and traffic variables that are not available in this input contract. The sample is generated by an ingestion hash and a second training-stage seeded subsample, which may affect statistical representativeness. No causal claims or production reliability guarantees follow from this initial model comparison. Model drift detection, coverage calibration and adaptive retraining will be developed and assessed in separate milestones.
